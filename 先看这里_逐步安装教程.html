1. 先看懂：要装哪两样东西

这是一套非官方、本地运行的 BOSS 直聘岗位研究工具。你需要同时安装Codex 本地插件和Chrome 扩展：前者告诉 Codex 如何检索、整理与核验；后者读取你已经登录、能够正常查看的 BOSS 网页。中间由本机连接服务传递任务和结果。

你登录的 BOSS 标签页 → Chrome 扩展 → 本机连接服务 → Codex 核验、统计 → Excel＋HTML

不需要购买 BOSS API，也不需要给本插件提供 API Key。你的 Codex 账号和模型使用仍按自身服务设置计费或消耗额度。插件不会训练模型、投递简历或替你联系招聘者。

Codex插件版本为0.3.0，Chrome扩展版本为0.2.0，本转发包是2026-10-19的代码与教程快照，含实际任务中的提取修正和预筛辅助。已在原电脑真实运行过；其他电脑、账号或BOSS页面仍需先验证，不能保证免验证码、任意抓取或固定速度。

2. 准备电脑与软件

  1. 本教程按 Windows＋日常使用的 Google Chrome＋可执行本地任务的 Codex 客户端编写。普通网页版聊天不能直接读取你电脑上的Chrome和本机文件。
  2. 确认 Codex 能正常对话并打开一个本地文件夹。若尚未安装，请从 OpenAI 官方入口获取与你账号适配的客户端；不要从本包寻找Codex安装程序。
  3. 确认日常 Chrome 可以打开 BOSS 直聘，登录并能看到一份完整职位描述。账号、密码、短信验证码由你自己填写。
  4. 需要 Python 3.10 或以上。先让 Codex 检查本机及其可用运行时，已有即可，不用重复安装。确实没有时，到 Python Windows 官方下载页安装适合电脑的版本；重新打开终端后检查版本。不熟悉命令可把报错交给Codex。
  5. 基础采集与CSV处理使用Python标准库；最终Excel/HTML由Codex使用任务环境的表格与文件工具制作，这两部分不是扩展按钮自动输出的。

3. 下载后先解压，选对文件夹

  1. 把收到的 ZIP 保存到电脑，右键选择“全部解压缩”，不要直接在压缩包里运行。
  2. 建议解压到固定位置，例如 C:\CodexBOSS\boss-research。也可以放其他位置，后文示例路径相应替换。
  3. 打开解压后的根目录，应该看到 chrome-extension、plugins、01_安装连接_发给Codex.txt、02_通用岗位研究提示词.txt 和本教程；隐藏目录 .agents 也必须随包保留。
  4. 不要把 chrome-extension 单独挪走后删除其他文件。安装后也不要删除或移动整个目录；Chrome要持续读取这个文件夹。

成功标志：你打开的是已解压的完整根目录，而不是ZIP预览，也不是多套了一层的空文件夹。

4. 在 Codex 中安装研究插件

  1. 在 Codex 选择打开本地文件夹或项目，选择刚才的 boss-research 根目录。不同客户端按钮名称可能不同，关键是让当前任务可以读到这个目录。
  2. 用记事本打开 01_安装连接_发给Codex.txt，全选复制，粘贴到这个 Codex 任务并发送。让Codex完成环境检查、插件安装和本机服务启动。
  3. 如果需要你选择“信任这个文件夹”，请先确认它正是你解压的本包目录。若系统请求执行权限，按具体动作判断；不必把所有电脑权限永久开放。
  4. 插件安装后，如列表没有刷新，退出并重新打开 Codex；在同一目录建立新对话，确认“BOSS 岗位研究”已可用。不要仅凭安装命令执行过就认定成功。
  5. 若 Codex 没有CLI命令或插件界面不支持本地安装，让它明确说明并在当前任务直接读取本包SKILL.md运行，作为临时方式。不能将这种临时读取称为永久安装。

本地插件市场与安装结构参照 OpenAI官方插件文档。界面名称和安装能力可能随客户端变化。支持下列CLI的环境也可在根目录手动执行；若不支持，走插件目录的本地来源安装，别反复试未知命令：

codex plugin marketplace add . --json
codex plugin add boss-research@boss-research-local --json
codex plugin list

成功标志：Codex确认插件已安装/可用，或明确告知正在用临时读取方式；不是只说“可以帮你”。

5. 在日常 Chrome 安装页面采集扩展

  1. 打开平时登录 BOSS 的那个 Chrome 窗口。在地址栏输入 chrome://extensions，按回车。
  2. 打开页面右上角的开发者模式。窗口太窄看不到右上角时，先最大化。
  3. 点击左上方 “加载未打包的扩展程序”。有的Chrome版本显示为“加载已解压的扩展程序”，这是同一入口；不要点“打包扩展程序”。
  4. 出现选文件夹窗口时，进入本包根目录，选择里面的 chrome-extension 文件夹，点“选择文件夹”。不是选择ZIP、整个根目录、plugins目录，也不是单独选manifest.json文件。
  5. 确认扩展卡片名称为 BOSS 岗位研究 · 页面采集、版本 0.2.0，右下开关已开启。
  6. 点击 Chrome 右上角拼图“扩展程序”图标，在这个扩展旁点图钉。工具栏会出现一个B图标或Chrome生成的默认图标。

成功标志：能打开扩展弹窗，看到“本机连接码”“连接并交给 Codex”“继续自动任务”“暂停自动任务”。这时扩展已装好，但还没配对。

本步骤依据 Chrome官方加载扩展说明；首次安装不需要点Playwriter。若公司策略禁止未打包扩展，请联系设备管理员，不绕过策略。

6. 启动本机服务，拿到自己的连接码

  1. 回到刚才的 Codex 任务，说：“请启动本包的本机连接服务，给我本次六位连接码；已有同任务服务先复用。”如果第4步已经给了码，不重复启动。
  2. Codex应使用本任务下 work/boss-bridge 保存独立状态，本机服务监听 127.0.0.1:19763。不要开放路由器或公网端口。
  3. 记下它这次给你的六位数字。每台电脑/新状态自行生成，本教程不提供通用连接码，不能照抄别人截图里的旧码。

仅供会用终端者手动启动（从包根目录执行，已有同端口服务时先核对，不强行结束进程）：

python .\plugins\boss-research\skills\boss-research\scripts\bridge.py --work .\work\boss-bridge serve

这个终端保持打开；出现监听地址说明服务已启动。另开本地终端仍在相同根目录执行下行取码。若你用的是 py 或绝对Python路径，请一致替换；普通用户交给Codex执行即可。

python .\plugins\boss-research\skills\boss-research\scripts\bridge.py --work .\work\boss-bridge pair-code

成功标志：Codex确认服务已运行，并给出本次六位码。不要把bridge-state.json的长令牌发到群里。

7. 把原来的 BOSS 标签页连接给 Codex

  1. 切换到你正常登录、可以显示职位的 BOSS标签页。不要停在扩展管理页、Google搜索页或空白页配对。
  2. 点工具栏的 BOSS研究扩展，输入第6步取得的六位数字。
  3. 点击 “连接并交给 Codex”。看到“已连接，等待Codex任务”等状态后，回到Codex说“已连接，请先验证页面”。
  4. Codex应检查最近回传、搜索条件与一份完整JD的标题/公司/城市/链接是否对应。你可以对照屏幕看这份JD是不是同一岗位。
  5. 如果出现登录或验证码，你在这个原标签页正常完成，随后打开本扩展点击 “继续自动任务”，告诉Codex“已继续”。

成功标志：Codex实际读到可追溯的列表和完整JD，数据出现在本机记录中。扩展显示“已连接”本身不等于已采集成功。

一台电脑默认只有一个19763端口服务；一次让一个Codex任务控制绑定页。多人同时研究，应各自在自己的电脑/账号操作，不共享登录状态和配对令牌。

8. 填自己的岗位：先试采，再扩展

  1. 连接验证成功后，双击包内的填写研究需求.html。
  2. 填研究岗位、行业、城市、有效数量和重点，其他可以留空由Codex先读JD判断。
  3. 点击“生成我的研究提示词”，再点“复制完整提示词”，发送给已连接的Codex任务。也可以下载TXT或research.json放到任务目录。这个填写页本身不会采集。
  4. 先看最多10份试采Excel，确认职责范围、字段和分类，再告诉Codex按你填的有效样本目标继续。
  5. 若研究销售、开发、客服或经理，就以这些岗位实际职责为目标，不套用AI训练案例的排除规则。管理岗按相关职责保留并标层次。

研究模板为通用岗位版，AI训练师只是examples中的一个案例。默认有效目标100可自行修改，整个研究需要实际JD核验、去重和报告制作，不是安装完自动出现全量数据。

9. 日常使用、暂停、恢复与更新

  • 能否浏览别的网页？通常可以切到其他标签或其他窗口。不要在被绑定的BOSS标签页里另开网站、手动改搜索条件或同时点岗位，以免与采集导航冲突。
  • 关闭扩展小弹窗：一般不停止任务。真正暂停请点“暂停自动任务”，也可在Codex说暂停。
  • 恢复：先让Codex确认原服务与数据检查点，再在原BOSS页点“继续自动任务”。恢复语句见03文件。重启电脑后需要重新启动本机服务；通常不必重装扩展。
  • 防止意外停止：采集期间保持Chrome、服务、Codex及网络可用，避免系统休眠、合盖睡眠或关闭绑定标签页。后台标签页节流、额度和访问限制都可能影响速度，不能承诺无人值守一定完成。
  • 定时回查：想半小时后自动报告，要让Codex实际创建支持的提醒/任务并确认成功。仅说“我半小时后回来”不代表已安排；不能调度时需明确告诉你。
  • 更新扩展：覆盖你原来的chrome-extension源码后，在chrome://extensions里点该卡片的圆形箭头重新加载，再回BOSS页继续。更新background/manifest尤其需要重新加载。
  • 更新Codex插件：按本地市场刷新或重新安装流程更新缓存，再重开对话；只改解压源码不保证已安装缓存自动更新。
  • 卸载：Chrome扩展卡片点“移除”；Codex插件管理里卸载或用支持的CLI移除。研究数据先备份，再由你决定是否删除本地目录。

10. 常见卡点：对照着处理

遇到的情况按顺序处理
找不到“加载已解压的扩展程序”先开开发者模式、最大化窗口，找“加载未打包的扩展程序”。这是同一功能的不同中文名称。
提示缺少manifest或无法加载确认ZIP已解压，选的是直接包含manifest.json的chrome-extension目录，文件没有被移动或删掉。
工具栏没有B图标点击拼图图标找到本扩展并固定。默认图标不一定与原电脑完全相同，以扩展名称为准。
“请先切换到BOSS标签页”在真正的zhipin.com岗位页面打开扩展，不能在chrome://extensions或Google搜索页配对。
连接失败、Failed to fetch让Codex查本机服务是否运行、19763是否被其他任务占用、扩展是否获BOSS和本机服务权限。不要开放公网或盲杀进程。
连接码不正确让Codex从当前work目录重新读取六位码，核对服务归属；勿把示例码、旧电脑码或另一任务的码混用。
已连接却没有岗位数据可能只是等待任务，也可能页面没加载、尚无命令或被阻断。让Codex检查最近回传和命令状态，先核验1份JD，别直接宣称成功。
验证码、重新登录、拒绝访问暂停采集；你在原页面手动处理，恢复后点“继续自动任务”。不能绕验证、改身份或反复刷新碰运气。
突然新开了一个未登录的Chrome告诉Codex复用普通扩展绑定页，不要独立浏览器或Playwriter。确认它没有误走另一个工具的浏览器会话。
页面空白或JD公司对不上先停，记录链接和原因，核对当前真实页面与提取规则；错绑数据不纳入核心。不要继续凑数。
断线后又从零开始/同一链接反复打开使用03恢复语句，复用原work、token和检索检查点；先检查pending/running任务，不重复入队。
原始JD很多，有效数少让Codex解释分类和缺失证据，检查销售、实施开发等混入；提升可见列表预筛，但仍读完整职责，不能降低有效标准。
没有codex命令或本地插件入口让Codex检查当前客户端能力；临时读取SKILL.md可在有本地执行能力的任务里工作，但不伪称永久安装。只有网页聊天时需换到支持本地执行的环境。

11. GitHub版包含什么

包含通用Codex插件、Chrome扩展、可配置列表优先级辅助、详细安装教程、岗位需求填写页、完整通用提示词、产品经理配置示例、AI训练师研究示例和发布说明。

没有任何原使用者的岗位数据、账号、登录态、配对码、长令牌或运行检查点。每人独立登录和配对。研究数据存在任务work/outputs目录，已在.gitignore忽略，不提交到GitHub。扩展只传本机服务；Codex处理的内容可能由模型服务处理。

目标样本量、城市、行业、关键词和筛选边界都可改。不要把“排除销售”写死在通用插件里；只有用户本次配置了排除词才用于预筛，最终仍读职责判定。
